## A. Summary

- **Before:** the base was already strong: `__Host-` Strict cookies backed by server sessions, a global CSRF filter, PBKDF2 Identity hashing, hashed one-use codes with constant-time checks, MFA, Turnstile, no SQL, GraphQL, SAML, WebSockets or JWT sessions. Recon found real gaps:
  - stored rich text was sanitized only in the browser, and the editor sink was not sanitized at all;
  - OpenAPI was open to any signed-in account;
  - HSTS was 30 days and `Server: Kestrel` was sent;
  - the capability report was wrong;
  - an authenticator code could be replayed inside its window;
  - there was no forgotten-password reset, no self-service account closure or data copy (both promised by the privacy page), no age check, and no security-event logging.
- **After:** all of these are fixed, with tests. The trusted-hop client address is explicit. Startup now refuses half-set secret settings. 581 backend tests pass (80 unit, 501 integration). The sweep shows that every one of the 600+ protected endpoints answers 401 to an anonymous caller, and that the 43 anonymous endpoints are exactly the reviewed list.
- **Top remaining risks:**
  1. No breached-password screening (needs an owner decision about a third-party call).
  2. Uploaded photos keep EXIF metadata, location included, because stripping and re-orienting needs an image library.
  3. HSTS preload, and a WAF/CDN in front of the apex, are owner decisions.
  4. Password reset works in production only once Resend is configured.
  5. No per-day caps on code emails or broadcasts (in-app only today).
