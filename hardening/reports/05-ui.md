# 05 UI, design and accessibility

Agent 05, branch `hardening/05-ui`, cut from `fullstack-hardening` at `0e0ad78`, 22 November 2026. Only files under `frontend/` changed (plus this report and `hardening/handoffs/from-05-ui.md`); no backend or test-project file. Nothing was deployed; production was not contacted.

How things were measured (all local, against the test-only host `ParishLife.EndToEnd`, Turnstile off unless stated):
- **axe-core 4.14.1** (taken from the npm cache's Lighthouse, not added to the project), injected by a scratchpad Playwright script into **230 page states**: the public pages signed out (sign-in, sign-up, home, a parish page, its request page, an unknown parish, product page, privacy, terms, cookies) in English and Arabic, then every screen of every fixture role's menu (priest and member in English and Arabic, the priest also in dark mode; operator, bishop, secretary, treasurer, leader, visitor in English). Tags: WCAG 2.0/2.1/2.2 A and AA plus best practice. The same script ran on a build of the base commit (`0e0ad78`, second host) for "before".
- **Lighthouse 12.8.2** (`npx --offline`, Playwright's Chromium) mobile: accessibility and performance on the sign-in page, the public home and the product page.
- **Keyboard-only walk** (Playwright, keys only) of sign-in, the forgotten-password panel, sign-up, the authenticator step, My account and the close-account drawer.
- **Devices and widths:** a Playwright script that opens the public pages (EN/AR) and a signed-in role's screens (EN/AR) and reports any horizontal overflow, with screenshots.
- **End-to-end** with `E2E_CHANNEL=chromium`, including the new `e2e/ui-states.spec.mjs`.

## A. Summary

- **Accessibility:** axe went from **10 of 230 page states clean (6 rules, 384 + 90 + 31 + … nodes) to 230 of 230 clean**; Lighthouse accessibility on the sign-in page and public home went 94 and 95 to **100**. The causes were names that did not match visible labels, skipped heading levels, a verse hidden from screen readers, unnamed dropdowns and landmarks, white panels in dark mode, and (found by the keyboard walk, not by axe) an authenticator step that reused the username field, so a keyboard user landed nowhere and a typed code was appended to the email address.
- **Handoffs done:** route splitting (portal entry **1,674.55 KB to 616.04 KB**, gzip 486.39 to 196.34 KB) with a page skeleton; the **double-click Delete data loss** (High) fixed at the root and proven by an e2e test that fails on the old code; smaller window image for phones, WebP fallback photos and a preloaded backdrop; self-hosted print fonts; honest password-reset copy; the closure wording; the cookie link and request-form privacy note; the static sitemap removed (03 sweep S2); silent catches handled.
- **Design system:** dividers are alpha tints; fields got a solid edge that clears 3:1 (it was 1.32:1, failing WCAG 1.4.11 everywhere); nested radii, icon stroke weights, OKLCH colour wheel, scroller edge fades, dark-mode elevation by lighter surfaces, `dvh`.
- **Feels finished:** every button that waits for the server shows a spinner and takes no second press; every control shows a press; skeletons instead of blank or text-only loading; plain-language, bilingual errors with the API's trace id as a reference; an offline banner in the portal and an offline page from the service worker; real links in the phone bar; the largest screen split.
- **Not done or not verified:** the integrator's authorised merge of `fullstack-hardening` was refused by this machine's permission system (handoff 1); Safari/iOS could not run (Playwright's WebKit crashes on this macOS, so Apple devices were emulated in Chromium); the portal does not register the service worker itself (handoff 2).
