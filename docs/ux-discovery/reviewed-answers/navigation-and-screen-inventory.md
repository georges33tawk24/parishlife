# Navigation, screen inventory and interaction states

Proposed textual prototype annotations, not a claimed interactive prototype. Public and staff use one product vocabulary; the selected role shapes tools within one combined home. One role opens directly; multiple available roles require deliberate choice. Personal content stays within the same shell, subject to actual account/person permissions.

## State vocabulary and fixed interaction rules

| State | Visible feedback and action | Focus/recovery |
| --- | --- | --- |
| Loading | Loading {permitted collection}; retain safe previously shown context, no fake zero/count | Announce busy region; do not shift focus or enable consequence before data ready |
| First use | No records yet; explain permitted setup/Create action; noncreator gets actual office/help route | No sample balances or default parish silently selected |
| No matches | No matching permitted results; show active filters and Reset/Change search | Keep query and result position; never confirm restricted existence |
| Required/invalid | Field-specific error plus linked summary; preserve values except secrets | Focus summary/first error; labels and error association work by keyboard/screen reader |
| Denied/unavailable | This item is unavailable or you do not have access. Back / allowed Home / nonrevealing support | Close stale private view; no cached title/name/amount in error screen |
| Unconfigured | This service is not available here yet; actual manual/office route or allowed setup task | No active fake provider/payment/delivery control |
| Unsaved/saving | Unsaved changes / Saving; explicit Save where needed; draft autosave never submits | Back/close/switch offers supported Save draft, Discard, Stay; failed save prevents navigation-as-success |
| Saved | Saved at actual time; record reference and real timeline result | Persistent consequence record, short toast optional; do not infer all attachments/messages succeeded |
| Conflict | This record changed; compare original/submitted/current; Reload/reapply/reconcile | Keep permitted draft; do not overwrite newer data or steal focus during edit |
| Connection lost/unknown outcome | Connection required. This action has not been confirmed. Check result/retry same operation | No authoritative offline payments/approvals/check-in/reservations; safe manual event procedure separately trained |
| Partial result | Primary record saved; named attachment/delivery step failed; Retry failed step | Primary transaction not repeated; persistent component state and assigned follow-up |
| Cancelled/closed/archived | Actual reason/outcome/effective date; permitted correction/reopen/history action | Do not show live approve/release controls for terminal or revoked record |

Every SC surface below uses these states, specialized by its listed complications; they are part of that screen’s acceptance inventory. Confirmations name actual actor/capacity, target parish/person/reference, exact effect, recipient/amount/version, reversibility and required reason. Read-only browsing needs no approval dialog. Short edit drawers return to collection position; complex flows use stable full pages and mobile full-screen variants.

## Language, mobile, keyboard and print annotations

Language switching preserves route, target parish/record, permitted draft values, filters and scroll. Arabic mirrors layout/directional navigation but isolates phone/email/URLs/IDs/currency fragments left-to-right; do not reverse chronological or media-play meaning indiscriminately. Personal names retain supplied script; English/French official spelling may be identical when actually supplied. Proposed digits: Latin digits for IDs, phone, machine dates and money; localized month-name display avoids ambiguous date order. Operational print uses parish-local 24-hour time; date-only anniversary never shifts with viewer travel.

Phone cards retain parish/reference/subject/stage/next actor/date and actual amount+currency where relevant. Calendars/attendance matrices offer scroll with sticky labels plus list alternative; family diagram has ordered relationship list. Drag-and-drop has Move/Assign controls. Dialog focus is trapped while open and returns to launching control; Escape/Back invokes supported draft rule. Upload selection/camera optional; retained files and failed file distinguished.

Propose WCAG 2.2 AA as the design verification target: normal text contrast 4.5:1 (large text 3:1), visible keyboard focus, 200% text resize, reflow checks, keyboard operation, and non-drag alternatives. This is a design target, not compliance certification or a claim of Lebanese legal applicability. Validate with intended older staff, Arabic screen-reader users and real office printers. [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/).

Proposed uncoached task targets for prototype review: find a published parish/time within 2 minutes; ordinary request or registration within 6 minutes excluding obtaining documents; clerk evidence correction within 3 minutes; priest instruction recording within 2 minutes; room conflict resolution within 5 minutes; single-person event check-in within 30 seconds once eligible. These are proposed usability targets, not actual measured performance or service guarantees. Any wrong-person release, unauthorized pickup/access, fabricated official approval or duplicate financial movement is a zero-tolerance blocker; other recoverable input errors must be discoverable and correctable without coaching.

Actual screen prototypes, small-phone (proposed 360px), laptop (1366px), zoom/reflow, EN/FR/AR, keyboard/screen-reader and multi-page A4 print validation remain outstanding under U14. Both initial parishes and a no-secretary setting require named actual reviewers.
